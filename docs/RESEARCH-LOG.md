# سجلّ الأعطاب والأبحاث

> **لماذا يوجد هذا المستند؟**
> التوثيق العادي يقول *ما فُعل*. وهذا يقول *ما فُعل أولاً وفشل، ولماذا*.
> بلا هذا، من يعود للمشروع سيُعيد نفس الأخطاء — بعضها كلّف عدّة دورات.
>
> **القاعدة الجامعة:** ما يُقاس آلياً لا يُحكم عليه بالعين. أخطر عطبين في المشروع كانا **يبدوان سليمين تماماً**.

## العطب ٢ — الطول: ١٣٫١ شاشة على الهاتف

**التشخيص لم يكن «النصّ كثير»** بل ثلاثة مصادر مستقلّة للفراغ:

**أ) `line-height: 1.95`** — مُضاعِف لا مقدار. على الأسطر الطويلة يُنتج فراغاً تراكمياً هائلاً. → `1.78`.
تغييرٌ لا يُلحَظ في السطر الواحد، ويوفّر شاشةً كاملة.

**ب) الهواء الزخرفي يتضاعف** — ٦ فواصل `.lx-orn` × ٧٢px = **٤٣٢px**، نصف شاشة هاتف من العدم. → `clamp()`.

**ج) الحشو المزدوج عند التقاء المكوّنات** — الأب فيه `padding` والابن فيه `padding`، فالفراغ ضعفان. → فُحصت حدود كل مكوّن.

**النتيجة:** ١٣٫١ → **١٢٫٢ شاشة**، بلا حذف أي معنى.

> **الدرس:** الطول الزائد نادراً ما يكون سببه النصّ. غالباً هو **فراغ متراكم من مصادر متعدّدة**، وكل مصدر يبدو صغيراً وحده.

## العطب ٣ — الصور باردة تشاجر اللوحة

| | |
|---|---|
| **العَرَض** | الصفحة تبدو **مرقّعة** لا موحّدة |
| **السبب** | صور القاعات بإضاءة بيضاء/باردة، فالأزرق فيها يشاجر البنّي والذهبي |
| **العلاج** | `filter: saturate(1.06) contrast(1.04) hue-rotate(-8deg)` على `.ls-fig img` و`.ls-svc img` |

**التحقّق كان بالبكسل من الصورة المُصوَّرة من المتصفّح** — لا من ملف CSS:

| الموضع | `B − R` | الحكم |
|---|---|---|
| معرض يسار | **−12.9** | دافئ ✅ |
| معرض يمين | **−32.9** | دافئ ✅ |

> **الدرس:** تحقّق من **البكسل المُرسَل**، لا من ملف المصدر. وجود القاعدة في CSS لا يُثبت وصولها للمتصفّح.

**مصيدة مكتشفة أثناء العلاج:** `filter` **يُستبدل ولا يُضاف** عند `:hover`. فأي قاعدة hover تضع `filter` لازم تُعيد كتابة التدريج كاملاً، وإلّا بردت الصورة لحظة اللمس.

## العطب ٤ — العلامة المائية (أربع محاولات فاشلة، والقياس هو الذي حلّها)

| الإصدار | ما جُرِّب | لماذا فشل |
|---|---|---|
| ١ | لصق الشعار كما هو | ثقيل، يُفسد الصورة |
| ٢ | تصغير + تخفيف | يذوب على الخلفيات الفاتحة |
| ٣ | هالة مضادّة | تحسّن، لكن الجسم ما زال مصمتاً |
| ٤ | صبغ بلون ذهبي واحد | ❌ **بيضة رمادية مصمتة بلا قهوجي ولا دلّة** |
| ٥ | **نقشٌ محفور** | ✅ |

### نقطة التحوّل: قِستُ الشعار بدل أن أُعدّل القيم

بعد فشل الإصدار ٤، لم أُجرّب قيمة شفافية أخرى. قِستُ `logo-official.png` بـ `numpy`:

```
قناة الشفافية  →  شبه ثنائية: ٨٠٦٣١١ بكسل عند صفر · ٢٣٣٨١٥ بكسل فوق ٢٢٤
الإضاءة        →  انحراف معياري ٦٧٫٧ · أدنى ٣٥٫٦ · وسيط ١٢٧٫٣ · أعلى ١٧٦٫٨
                  ٤٧٪ من الجسم عند L≈36 (حبر كحلي) مقابل L≈177 (رمليّ)
```

**التفسير:** الشفافية تحمل **الصورة الظاهرية للبيضة لا تفاصيلها**. التفاصيل — الشماغ، الوجه، الدلّة، الفنجان — تعيش في **تضاد اللون**.

**النتيجة المنطقية:** صبغُ الشعار بلون واحد = إلغاء تضاد اللون = **محوُ التفاصيل حتماً**.
أي أن **فرضيّة الإصدار ٤ كانت خاطئة من أصلها، ولا قيمة شفافية كانت لتُنجيه.** لو ظللت أُعدّل الأرقام لبقيت أدور في حلقة إلى الأبد.

### العلاج: نُعيد بناء الشفافية من دكانة الحبر

```python
INK_L, BG_L = 40.0, 172.0          # مقاستان من الملف لا مُخمَّنتان
t     = (BG_L - L) / (BG_L - INK_L)
alpha = A * t ** 0.88               # 0.88 يُسمّن الخطوط الرقيقة لتصمد بعد التصغير
```

الحبر الكحلي → خطوط ذهبية معتمة. البيضة الرملية → **نافذة شفافة تماماً**.
**علامة تُؤطّر الصورة ولا تغطّيها** — الكرواسان يُرى من خلال البيضة.

**التحقّق البصري:** كبّرت الزاوية الموقّعة من ٣ صور (خلفية فاتحة، داكنة، بيضاء) → التفاصيل محفوظة و«كيف الضيافة» مقروءة في الثلاث.

📁 الأداة: [`research/scripts/watermark_engrave.py`](../research/scripts/watermark_engrave.py)
🖼 الدليل: [`research/evidence/watermark-v5-zoom.png`](../research/evidence/watermark-v5-zoom.png) · [`logo-composition-measure.png`](../research/evidence/logo-composition-measure.png)

> **الدرس الأهم في المشروع:** لا تُعدّل القيم قبل قياس المادة. القياس قد يُثبت أن **الفرضية** خاطئة لا الإعداد — وحينها لا ينفع أي ضبط.

## العطب ٥ — الباركود مرفوض بـ HTTP 400

| | |
|---|---|
| **العَرَض** | الباركود يظهر كأيقونة صورة مكسورة (وجدته **بعيني** في الصورة الملتقطة) |
| **التشخيص** | الملف المباشر → **200**. مُحسِّن الصور → **400** `"url" parameter is not allowed` |
| **السبب** | `next.config.js` يقصر `images.localPatterns` على `/images/**`، والملف كان في `/brand/` |

**العلاج:** نقل الملف إلى `/images/brand/` — **لا توسيع السياسة**.
`localPatterns` قائمة سماح أمنية؛ إضعافها لأجل ملف واحد يفتح ثغرة دائمة مقابل راحة لحظية.

> **الدرس:** حين يمنعك قيد أمني، **انقل عملك إلى داخل القيد** لا تُوسّع القيد.

| | |

## العطب ٧ — أخطر عطب في المشروع: مُحسِّن الصور يقتل الباركود

**هذا العطب لا تراه العين أبداً.** الباركود كان يُرسَم على الشاشة **سليماً تماماً وجميلاً** — وكان **ميتاً**.

بعد إصلاح المسار، أعاد المُحسِّن **200**. ولم أكتفِ. جلبتُ **مُخرَجه الفعلي** وفكَكتُه:

```
served (384, 384) WEBP
decode -> FAIL
```

**السبب:** المُحسِّن يحوّله WebP بضغط ضائع عند `q=75`. ووحدات الباركود **حدود حادّة بين أسود وأبيض**، والضغط الضائع يُلطّفها فتنزل تحت حدّ القراءة.

**الأثر لو نُشر:** العميل يصوّر الباركود ولا يُفتح شيء. خسارة عميل صامتة تماماً — لا رسالة خطأ، ولا شكوى، ولا أثر في أي سجلّ.

**العلاج:**
```tsx
unoptimized   // شرط صحّة لا مقايضة أداء — الملف ٧٠ ك.ب فقط
```

**التحقّق بعد الإصلاح:**
```
200 image/png · served (984,984) PNG
decode -> ['https://keifaldiafa.com/social']
```

> **الدرس:** بعض المواد **تُفسدها المعالجة المفيدة عادةً**. تحسين الصور نافع لكل صورة في الموقع، وقاتل للباركود وحده. فالقاعدة العامّة لا تُطبَّق بلا فحص الحالة الخاصّة.

## العطب ٨ — اختراع صنف CSS موازٍ

**ما حدث:** كتبت `lx-cta` لشريط النداء الأخير. `grep` أثبت أنه **غير موجود** — والنمط الحقيقي في `LocalServicePage.tsx` هو:

```tsx
<div className="ls-band" data-rise3d>   {/* يوفّر حشوه وتوسيطه بنفسه */}
```

**اكتُشف قبل البناء** بفحص الأصناف. لو مرّ، لظهر شريطٌ بلا ستايل.

> **الدرس:** قبل أي markup، `grep` على كل صنف. اختراع صنف موازٍ يُنتج مظهرين متشابهين لا يتطابقان — ويتباعدان مع كل تعديل لاحق.

## قرار تصميمي: لماذا لا نستعمل ألوان المنصّات؟

**الخيار المرفوض:** أيقونات إنستغرام/تيك توك/سناب بألوانها الأصلية.
**السبب:** صفٌّ من ستّة ألوان متضاربة يكسر لوحة الصفحة البنّية-الذهبية، ويقرأ كشريط أدوات عام لا كتصميم فخم.
**الاختيار:** كلها بنفس الأساس الذهبي المجسّم — **الأشكال محفوظة، والتعرّف يقع على الشكل لا اللون.**

## قرار تصميمي: الباركود كريمي والصفحة داكنة

يبدو مخالفاً للوحة، وهو مقصود: **الماسح يحتاج قطبية موجبة** (حبر داكن على ورق فاتح). قلبُها يفشل مع بعض ماسحات أندرويد.

**فالفخامة تدخل حول الرمز لا فوقه:** حدّ ذهبي، ظلّ حلقيّ، ارتفاع عند اللمس. أي تدرّج أو حجاب **فوق** الرمز يقتل القراءة.

**والحجم مُبرهَن:** `pyzbar` يُفكّه حتى ١٨٠px ويفشل عند ١٤٠ → العرض ٢٢٤/٢٨٨px = **ضِعف هامش الأمان**.
